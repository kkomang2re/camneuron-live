# 캠뉴런 라이브

PC 없이 폰 하나로 치지직에 야외 방송을 하는 Android 앱. 폰 카메라·마이크를 RTMP로 치지직에 바로 보낸다.
캠뉴런(폰을 OBS 캠으로 쓰는 앱)에서 갈라져 나왔고, 이제 따로 관리한다.

**출시하지 않고 혼자 쓰는 앱이다.** 스토어에 올리지 않으며 직접 서명한 릴리즈 빌드를 내 폰(Galaxy S25 Ultra)에 깔아 쓴다.
그래서 처음 쓰는 사람을 위한 안내나 여러 기기 대응보다, 야외 방송에 실제로 필요한 것과 이 폰에서의 안정성을 먼저 본다.

## 야외 방송 기능

- 송출: 1080p/720p, 30/60fps. 폰이 뜨거우면 처리량(60→30fps, 위젯 그리기)을 줄이고, 네트워크가 약하면 비트레이트를
  낮췄다가 좋아지면 8초마다 한 단계씩 되돌린다. 폰 안에서 2초 넘게 밀린 영상은 버리고, 3초 넘게 밀린 소리는
  건너뛰어 방송 지연이 쌓이지 않게 한다 (아래 "지연 측정"). 끊기면 다시 연결한다.
- 방송 중 상태: 방송 시간, 보내는 속도, **치지직에 실제로 떴는지와 시청자 수**, 배터리·온도, **마이크 음량 막대**.
- 조작: 마이크 끄기, 화면 가리기(자리 비움), 카메라 전환·줌·초점·노출·뷰티, 플래시, 손떨림 보정.
  방송 중에 카메라를 바꿔도 연결과 영상 크기는 그대로다 (전면 카메라가 60fps를 못 내면 프레임 수만 낮춘다).
  바꾸지 못하는 폰에서는 이전 카메라로 돌아가 방송을 잇는다.
- **화면 잠금**: 터치를 막고 화면을 어둡게 한다 (주머니·짐벌, 배터리·발열). 길게 눌러 푼다.
- 방송 종료는 한 번 묻는다 (잘못 눌러 끝나지 않게).
- **작은 창(PiP)**: 방송 중에 홈 화면이나 다른 앱으로 가면 방송 화면(미리보기와 위젯)이 작은 창으로 남는다. 작은 창을
  누르면 앱으로 돌아오고, 닫아도 방송은 계속된다. 방송이 끝나면 작은 창도 닫힌다.
- 방송하지 않는 채로 화면에서 벗어난 지 10분이 지나면 앱을 스스로 끈다 (`IdleExit`. 방송 중에는 끄지 않는다).
- 치지직: 로그인하면 스트림 키를 받아 오고, 제목·카테고리·태그를 바꾸고, 채팅을 보고 쓴다.
  후원·구독은 진동과 함께 소리 내어 읽고, **채팅도 읽어 줄 수 있다** (걸으면서 방송할 때).
- 위젯: 치지직 채팅창·후원 알림, 투네이션·치지직 **후원 알림과 영상 후원** 등 OBS 브라우저 소스용 주소를 방송 화면에 얹는다.
  주소를 넣으면 알맞은 자리에 저절로 놓이고, 방송 중에도 옮기고 크기를 바꿀 수 있다.
  위젯의 소리는 폰 스피커로 나와 마이크로 들어간다 (이어폰을 끼면 시청자에게 안 들린다).
  후원이 멈췄을 때는 "위젯" → **후원 넘기기**나 **새로고침**(위젯 페이지를 다시 부른다).
  후원 넘기기는 지금 나오는 후원 하나를 바로 가리고 소리를 끈 뒤, 그 후원이 끝나는 순간 다시 보인다. 후원이 줄지어
  밀려 있어도 한 번에 하나만 넘어가고 다음 것은 처음부터 제대로 나온다. 넘긴 후원의 목소리·효과음은 페이지에 붙이지
  않고 튼 것, Web Audio로 튼 것도 함께 꺼진다.
  시간이 지나야 넘어가는 위젯은 페이지의 시계를 빨리 감아 1~2초 만에 넘긴다. 치지직 영상 후원은 재생 시간을 서버가
  재서 앞당길 수 없다: 가려진 채로 그 영상의 시간이 지나야 다음 영상이 나온다. 페이지를 불러오지 못했거나 웹 페이지를 그리는 프로세스가 죽으면 스스로 다시 부른다.

시청자 수는 치지직 Open API에 없어 웹 플레이어가 쓰는 공개 주소(`api.chzzk.naver.com/polling/v2/channels/{채널}/live-status`)를
읽는다. 문서에 없는 주소라 언제든 안 될 수 있고, 그때는 그 줄만 "확인 중"으로 남는다. 혼자 쓰는 앱이라 쓴다.

## 모듈

- `app` (`com.camneuron.live`): 화면, 방송 세션, RTMP 송출, 치지직 계정·채팅·방송 정보, 위젯.
- `core` (`com.camneuron.core`): 카메라, 영상·소리 인코더, GPU 효과(뷰티·가리기·위젯 층), 발열·네트워크 조절.
  캠뉴런의 core를 복사해 온 것이라 이제 캠뉴런과 따로 바뀐다.

## 빌드

JDK 17과 Android SDK가 필요하다 (`local.properties`의 `sdk.dir`).

```
gradlew testDebugUnitTest assembleDebug
```

디버그 APK: `app/build/outputs/apk/debug/app-debug.apk` (패키지 `com.camneuron.live.debug`). 시험용이다.
빌드한 PC의 디버그 키(`~/.android/debug.keystore`)로 서명되어, 다른 PC에서 빌드한 것은 덮어 깔 수 없다.

릴리즈 APK (폰에 두고 쓰는 것):

```
gradlew testReleaseUnitTest assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
```

`app/build/outputs/apk/release/app-release.apk` (패키지 `com.camneuron.live`). 디버그와 다른 앱이라 함께 깔리고,
설정(스트림 키, 치지직 로그인, 위젯 주소)도 따로 저장된다. 새 버전을 낼 때는 `app/build.gradle.kts`의
`versionCode`·`versionName`을 올린다.

릴리즈 서명 키는 저장소에 넣지 않는다 (`.gitignore`). 루트에 `keystore.properties`와 `keystore/camneuron-live-release.jks`가
있으면 서명하고, 없으면 서명하지 않은 APK가 나온다 (폰에 깔 수 없다). 키를 잃으면 깔린 릴리즈 앱 위에 새 버전을 덮어 깔 수
없고, 지우고 다시 깔면 폰에 저장한 설정이 사라진다. 그래서 키는 따로 보관한다.

GitHub에서 빌드하기 (`.github/workflows/apk.yml`): main에 올라올 때나 Actions에서 직접 실행할 때 릴리즈 APK를 빌드해
Releases에 올린다. 저장소 Secrets에 `RELEASE_SIGNING`(위 두 파일을 묶은 값)이 있으면 같은 키로 서명해, 받은 APK를 깔린 앱
위에 덮어 깔 수 있다. 없으면 빌드마다 다른 임시 키로 서명한다 (덮어 깔 수 없다). 값을 만드는 법:

```
tar -cz keystore.properties keystore/camneuron-live-release.jks | base64 -w0
```

## 지연 측정

`tools/net-sim/`: 앱의 실제 송출 코드(rtmp 패키지, NetGovernor, LiveNet)를 PC에서 돌려, 느려졌다 빨라지는 망에서 영상·소리가
가짜 서버에 얼마나 늦게 닿는지 잰다. Android SDK도 폰도 필요 없다. 카메라·인코더·치지직 서버는 들어 있지 않다.
시청자 플레이어는 단순한 모형으로 넣었다 (Sim.kt의 `Viewer`): 받은 것을 방송 시각 순서대로 1배속으로 틀고, 받아 둔 것이
떨어지면 멈췄다가 그 자리에서 이어 트는(따라잡지 않는) 플레이어. 망이 좋을 때의 지연은 5초로 놓았다.
**실제 치지직 서버와 시청자 앱이 이 모형대로 움직이는지는 확인하지 못했다.**

```
gradlew -p tools/net-sim installDist
tools/net-sim/build/install/net-sim/bin/net-sim walk out/walk.csv
python3 tools/net-sim/summary.py out/*.csv
```

망은 이름(good, dip, weak, walk, flap, blackout, mixed, outages, slow, crawl, barely, trickle, soak)으로 고르거나
`15x20000,150x150,30x20000`처럼 "초x속도(kbit/s)"를 직접 준다.

시청자 지연이 늘어난 채 돌아오지 않는 까닭: 폰이 늦게 보낸 것이 망이 좋아진 뒤 한꺼번에 닿으면, 따라잡지 않는 플레이어에는
그만큼이 쌓여 그 뒤로 계속 늦게 본다 (PC 웹 플레이어는 빨리 감아 따라잡는 것으로 보인다). 그래서

1. 폰 안에서 밀리는 시간을 묶는다: 영상은 2초, 소리는 3초 (`LiveNet`). 소켓 버퍼도 지금 비트레이트와 실제로 나가는 속도에
   맞춰 작게 둔다 (거기 든 것은 대기열이 모르는 밀림이다).
2. 그보다 밀린 것은 버리고, 그 뒤의 방송 시각을 당겨 끊긴 데 없이 이어 붙인다 (`MediaQueue`). 버린 만큼 방송에서 빠지는
   대신 한꺼번에 닿는 것이 없다.
3. 소리까지 건너뛰어야 했으면 망이 영상을 못 싣는 것이므로, 영상은 5초(되풀이되면 20초까지) 쉬었다가 다시 시작한다.
   그동안은 소리만 보내고 비트레이트를 도로 올리지 않는다.

1080p30 4.5 Mbps로 잰, 망이 다시 좋아진 뒤의 시청자 지연 (모형. 잴 때마다 조금씩 다르다):

| 망 | 시청자 지연: 0.0.10 → 0.0.11 | 건너뛴 소리 (0.0.11) |
|---|---|---|
| 계속 좋음 (20 Mbps) | 5.0초 → 5.0초 | 없음 |
| 30초 동안 2 Mbps | 5.0초 → 5.0초 | 없음 |
| 40초 동안 1.2 Mbps (최저 비트레이트보다 느림) | 5.6초 → 5.4초 | 없음 |
| 걷기: 45초 좋고 6초 1.5 Mbps | 5.5초 → 5.3초 | 없음 |
| 자주 나빠짐 (느려짐·4초 끊김·1 Mbps 반복, 5분) | 6.0초 → 5.0초 | 9초 |
| 6초 동안 완전히 끊김 | 8.0초 → 5.0초 | 3초 |
| 8초씩 여섯 번 끊김 | 10.0초 → 4.0초 | 36초 |
| 2분 동안 600 kbps | 7.7초 → 5.3초 | 3초 |
| 1분 동안 300 kbps | 10.6초 → 3.4초 | 15초 |
| 3분 동안 200 kbps (소리만 겨우 보낼 속도) | 15.2초 → 4.6초 | 39초 |
| 2분 30초 동안 150 kbps (소리도 다 못 보냄) | 23.3초 → 4.9초 | 30초 |

0.0.10까지는 소리에 시간 제한이 없어, 소리조차 다 못 보내는 망(폰이 뜨거워 통신이 느려질 때, 사람 많은 곳)이 이어지면
지연이 수십 초까지 늘고 망이 좋아져도 돌아오지 않았다. 지금은 그 시간만큼의 방송을 버린다: 망이 나쁜 동안 화면이 멈추고
소리가 군데군데 빠지지만, 좋아지면 바로 지금 장면으로 돌아온다. 5초보다 작은 값은 플레이어가 받아 둔 것을 다 써서 덜 쌓인
채로 이어 보는 경우다 (실제 플레이어는 다시 채울 것이다).

망이 갑자기 100 kbps 아래로 떨어지면 이미 소켓에 넣은 것이 10초 안에 빠지지 않아 다시 연결한다 (전과 같다).

## 테스트 도구

`tools/widget-skip-test/`: 후원 넘기기 스크립트를 실제 Chromium에서 시험한다 (playwright 필요). 후원 위젯이 다음 후원으로
넘어가는 여러 방식(산 시간만큼 되풀이, 1초마다 세기, 시계 보기, 글자 알림, 다른 사이트의 플레이어, 재생이 끝나야 넘어감,
서버가 시간을 잼)을 흉내 낸 페이지로, 지금 것만 넘기고 다음 것의 시간은 거의 깎지 않는지, 넘기는 동안 가려지고 소리가
꺼졌다가 다음 후원에서 되돌아오는지, 넘기지 않을 때 타이머·시계가 원래대로 도는지 본다.

후원이 줄지어 밀린 경우도 본다 (내용이 똑같은 알림이 틈 없이 이어짐, 소리 없는 알림, 읽어 주는 소리가 끝나야 넘어가는
알림, 영상이 이어짐, 서버가 시간을 재는 영상이 이어짐): 한 번 누르면 하나만 넘어가고 다음 것은 제 시간과 소리를 지킨다.
목소리도 본다 (페이지에 붙이지 않고 트는 소리, Web Audio, 화면이 바뀐 뒤에도 이어지는 목소리): 누르는 즉시 꺼지고,
다음 후원의 목소리는 제대로 나온다.

```
node tools/widget-skip-test/time-test.js app/src/main/assets/widget_time.js
```

`tools/rtmp-test/`: PC에서 폰 송출을 받아 보는 도구 (`adb reverse tcp:1935 tcp:1935`로 폰과 연결).

- `java Receiver.java 1935 out.flv 60`: RTMP를 받아 FLV로 저장하고 요약을 출력한다.
- `java FlvToMp4.java out.flv clip.mp4 [시작ms] [끝ms]`: 받은 영상을 MP4로 바꿔 폰·PC 플레이어로 본다.

## 지켜야 할 것

- 화면 글자는 한국어로 쓴다.
